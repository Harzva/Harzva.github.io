模型与 API 连接 ​

OpenBot 可以连接你选择的兼容 API 服务。每个 Bot 分别选择连接、模型和执行内核；主 Bot 与执行 Bot 可以使用不同服务。API 额度与订阅由你向服务商取得，OpenBot 目前没有官方账号、托管模型或代售入口。

先完成快速开始，再按照本页配置一条连接。接入成功后，需要网页操作的 Bot 还要单独启用浏览器工具。

准备三个值 ​

字段填写内容核对方法
Base URL服务商提供的兼容 API 基础地址保留服务商要求的路径，例如 /v1；不要填聊天网页地址
API Key你在该服务获得的密钥确认属于该地址对应的服务与项目
模型名称服务端接受的完整模型 ID按服务商控制台或 API 文档填写，名称展示相似不代表 ID 相同

Base URL 只接受 http 或 https，不能在地址里嵌入账号、查询参数或片段。是否支持工具、图像和所需参数，取决于所选模型与服务的实际兼容性；普通文字回复成功只证明聊天路径可用。

在界面中保存连接 ​

  1. 选中要配置的 Bot，打开它的模型接入设置。
  2. 新建命名 API 连接，填写易辨认的名称、Base URL、Key 和默认模型。
  3. 保存连接，并在当前 Bot 的“这个 bot 使用”中选择它。
  4. 在 Bot 的“模型名称”中确认实际模型；自定义模型填写完整 ID。
  5. 先发送一句短的文字请求，收到真实回复后，再测试工具任务。

“测试连接”检查接口可达性，不能代替实际模型回复，也不能证明浏览器能力。需要验证模型与执行内核组合时，使用内核指南中的主动健康检测。检测会发起实际请求，使用少量服务额度。

每个 Bot 如何选模型 ​

主进程根据已保存配置解析请求，界面临时传入的模型名和温度不能覆盖它。

Bot 的配置实际选择
providerId 指向命名连接使用该连接的地址和 Key
providerId 留空跟随应用当前默认连接
Bot 的 model 非空使用 Bot 明确填写的模型
Bot 的 model 留空使用所选命名连接的默认模型
最终没有有效模型名拒绝请求，要求先填写模型

例如，研究 Bot 可选择“研究服务”连接与模型 A，写作 Bot 选择另一条连接与模型 B。它们仍保留各自的身份、会话、文件与记忆。切换模型不会新建 Bot，也不会自动开启工具。

编辑一条命名连接的地址、Key 或默认模型，会影响所有引用该连接的 Bot。若只想调整其中一个 Bot 的服务，先新建另一条连接，再分配给它。切换到另一地址来源时，需要明确填写该服务的 Key，程序不会把旧地址的密钥自动带过去。

工具轮次开始时会固定模型、温度、地址和凭据。中途修改配置影响后续轮次；运行记录保留该轮实际使用的模型。失败不会静默改用另一服务。

配置结构与源码排查 ​

日常使用界面保存配置。开发排错时，可以对照 src/config.js 和主进程的 botApiSettings；下面只展示结构，不包含可用凭据：

json
{
  "profiles": [
    {
      "id": "research-api",
      "name": "研究服务",
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "",
      "model": "your-model-id"
    }
  ],
  "activeProfileId": "research-api"
}

对应 Bot 使用 providerId: "research-api"。Bot 的 model 可明确指定，也可留空继承连接默认值。示例中的 example.com 和模型名必须替换，空 Key 不会产生回复。

config.json 位于当前数据目录，权限为 0600。Key 由主进程使用，界面只取得掩码。默认连接也支持 OPENBOT_API_KEY、OPENBOT_API_BASE 等环境变量；命名连接不会借用环境变量中的凭据。不要把真实 Key 写进源码、Fleet 包或终端历史。

自建节点使用哪条连接 ​

Bot 选择“自建节点”后，日常聊天仍在 Mac；派给节点的任务使用节点数据目录中的模型配置。节点必须存在相同 ID 的 Bot，并配置自己的连接、模型、内核与工具权限。

Fleet 配置包保留 Bot 的 providerId、模型和内核，但不携带模型 Key。导入后在节点重新配置连接；本机显示“已接入”不能证明节点已准备好。完整步骤见自建 Linux Node。

常见问题 ​

现象下一步
接口可达但没有模型回复检查模型 ID、Key 权限、服务额度与服务端返回的错误
提示找不到 API 配置重新为 Bot 选择存在的命名连接，检查 providerId 是否对应
仍使用旧模型核对 Bot 的显式模型是否覆盖连接默认模型，并开始新一轮请求
切换服务后提示缺少 Key为新地址明确填写 Key，再保存与重新检测
聊天正常，浏览器任务失败检查模型图像/工具兼容性、工具开关与当前内核组合

下一步可阅读执行内核；准备让多个 Bot 协作时，继续贾维斯模式。

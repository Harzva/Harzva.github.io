自托管应用授权 ​

0.10.9 开发源码新增 Node 应用授权服务的首版：拥有者集中连接应用，按 Bot 分配只读动作，服务端保存授权凭据并代为调用。首个提供商为 GitHub；这不是已经上线的官方多租户云服务。

准备 ​

在自己的 Node 安全配置 OPENBOT_KEYS_PASSPHRASE，并为专用 GitHub OAuth App 配置 OPENBOT_GITHUB_CLIENT_ID、启用 Device Flow。直接运行 Node 时使用 --with-integrations 开启已有外部 Bot 入口；Docker 部署可设置 OPENBOT_WITH_INTEGRATIONS=1。Node 仍需配置有效 Bot、模型与入口调用权限。

应用授权仓独立于模型 Key 和 CLI 登录。它不会扫描或上传 Codex、Claude 等本地智能体的订阅信息。没有主口令时授权服务关闭，不阻止 Node 其他能力；没有 Client ID 时不能开始 OAuth。

连接并分配 ​

CLI 调用正在运行的 Node，公网用 HTTPS，SSH 本地转发可用环回 HTTP。通过自己的安全方式设置 OPENBOT_NODE_TOKEN，它是节点拥有者凭据：

bash
export OPENBOT_NODE_URL=http://127.0.0.1:14718
node node/app-authorizations-cli.js status
node node/app-authorizations-cli.js connect github --label '我的 GitHub'

命令显示 GitHub 官方验证地址与短码，由用户本人在浏览器确认。完成后默认不分配给任何 Bot。用实际连接 ID 和已有 Bot ID 替换以下占位符：

bash
node node/app-authorizations-cli.js grant CONNECTION_ID --bot BOT_ID --actions github.profile.read,github.repos.list
node node/app-authorizations-cli.js call CONNECTION_ID --bot BOT_ID --actions github.profile.read
node node/app-authorizations-cli.js revoke CONNECTION_ID --bot BOT_ID
node node/app-authorizations-cli.js audit

call 是拥有者 act-as 验证；真实 Node 外部会话的 Bot 使用 app_connections_list 和 app_connection_call，身份来自可信运行上下文。只有获准的动作可调用，模型不接触 Token，也不能创建或扩大授权。该真实工具入口当前仅限已开启原工具权限的主Bot，且来源非Hub；应用grant不会自动开工具权限。其他入口、非主Bot外部会话、普通 Mac 聊天和浏览器任务尚未接入这些工具，桌面授权面板仍待实现。

已验证的真实调用 ​

2026-10-20，本机独立 Node 已通过真实 GitHub Device Flow、身份读取、加密保存与正常重启读取。用户本人确认 read:user；完成连接时默认没有 Bot 授权。

云端 0.10.9 的默认主 Bot 随后通过实际 SDK stdio MCP 客户端完成 app_connections_list → app_connection_call → github.profile.read，读回 GitHub 真实身份资料。按 Bot 分配指定只读动作、撤销后拒绝调用的边界已验证。此处是真实 Bot 工具链，不以 CLI 的拥有者 act-as 调用代替。

该次调用审计为 actor=bot、kind=call、status=completed，并关联实际运行来源。成功后云 Node 与微信接收器正常重启，连接、Bot 授权、审计和外部任务状态保持。实际 MCP 客户端重交相同逻辑 request_id 时返回 duplicate=true 及原任务结果，没有新增 GitHub 调用；未确认的调用仍不自动重放。

GitHub 配额耗尽曾返回 403，该次调用如实失败，没有自动换号重试。配额恢复后显式发起新请求，才读回真实结果。任务标为 done 与应用调用成功分别核对；验证应用动作应同时查看工具结果和调用审计，不能只看主脑文字或任务状态。

本次云闭环只覆盖 GitHub 只读身份。它不代表 Mac 安装包已包含授权面板，也不代表自动 refresh、72 小时常驻、手机 App 公网 Hub 或新云双屏已验收。统一状态见支持范围。

撤销与运行边界 ​

disconnect CONNECTION_ID 删除本节点活动 Token 和全部相关分配，不等于在 GitHub 撤销 Token。调用前后均核权限，撤销会中止在途调用并拒绝迟到结果；重启不自动重放未确认调用。OAuth 请求只有 read:user，实际仅提供身份与仓库列表两项只读动作，不支持任意请求或仓库写操作。

授权仓使用加密原子保存，目录0700、文件0600。它依赖单拥有者 Node 的实例锁和可信数据目录，不是多进程共享数据库。5000条常规审计满额后停止接新工作，保留止权空间；先导出审计，再显式使用 audit-prune --through EVENT_ID 清理。损坏或提交不明时封闭，不自动恢复旧授权。

本版尚未实现 refresh token 的保存和自动续期；access token过期时会明确要求重连。无需关闭GitHub的Token过期设置来迁就原型，长期自动刷新将在后续独立验收。

接口位于 /api/v1/app-connections，仅节点拥有者凭据可管理；旧凭据领取或外部入口令牌不能管理。源码测试使用自有夹具，与上面的真实 OAuth、云主 Bot 调用分别记录。桌面授权面板仍待实现。

完整命令、容量、API与恢复约束见源码 docs/app-authorizations.md。继续阅读Node API、配置和部署。GitHub 配置方式见官方授权文档。

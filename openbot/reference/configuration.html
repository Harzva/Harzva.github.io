配置参考 ​

0.10.9 的应用授权服务使用独立加密仓。服务器设置 OPENBOT_KEYS_PASSPHRASE，GitHub OAuth另需 OPENBOT_GITHUB_CLIENT_ID；Docker外部Bot入口可选 OPENBOT_WITH_INTEGRATIONS=1。这不迁移下方现有模型/渠道凭据，也不改变它们的保存方式。

配置保存在各自运行环境的数据目录。桌面与 Node 独立保存配置；Fleet 包不携带模型凭据或活动浏览器会话，但可以包含记忆与摘要等资料。显式导入配置包与持续的多端同步是不同流程。

数据目录 ​

环境配置方式
Mac App默认使用应用支持目录中的 openbot 数据目录
源码开发使用 OPENBOT_USERDATA 指定独立目录
Node CLI使用 OPENBOT_HOME 或 --home
Docker Node默认挂载 /var/lib/openbot

升级前备份整个数据目录。回退旧版本时恢复与该版本配套的整套状态，避免混用不同代的任务与动作账本。

模型连接 ​

config.json 中的命名 API 连接使用以下主要字段：

字段含义
id连接的稳定标识，供 Bot 引用
name用户可读名称
baseUrl模型服务的兼容接口地址
apiKey该连接的私有模型凭据
model连接默认模型
json
{
  "profiles": [
    {
      "id": "my-provider",
      "name": "我的模型服务",
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "YOUR_PROVIDER_KEY",
      "model": "YOUR_MODEL_NAME"
    }
  ],
  "activeProfileId": "my-provider"
}

这是字段示例，example.com 不提供模型服务。请在应用中配置真实服务商信息；不要把真实 Key 放进源码或公开文档。

每个 Bot 的执行选择 ​

字段可用值与作用
idBot 的稳定 ID，节点与桌面配置需明确对应
providerId引用命名 API 连接
model显式模型；留空继承所选连接默认模型
harnessdsh、pi、legacy；留空跟随应用默认DSH
executionLocationlocal 或 node，用于任务与屏幕
toolsEnabled是否明确启用现有工具，不由模型或文档自动开启
agent已绑定的 CLI/ACP 执行器配置，沿用独立路径

工具轮次开始时固定模型、温度、地址与凭据，中途修改只影响后续轮次。缺少有效模型时明确失败，不临时换成别的模型。

Node 连接 ​

桌面保存 Node 地址与私有令牌。当前推荐地址为通过 SSH 转发后的 http://127.0.0.1:14718。

Node 主令牌保存在节点数据目录的 node.json，不是模型 API Key，也不是用户账号会话。默认启动日志不打印令牌，需要时在自己的节点终端显式执行 token 命令。

凭据目前保存在受权限保护的本地配置文件，而非系统钥匙串。私有目录使用0700，凭据文件使用0600；备份也需要保留对应保护。

Docker 运行配置 ​

/etc/openbot/node.env 指定已经校验的镜像 ID、数据目录和 Chromium 可执行文件。它不应携带模型 Key。

ini
OPENBOT_IMAGE=sha256:<VERIFIED_IMAGE_ID>
OPENBOT_DATA_DIR=/var/lib/openbot
OPENBOT_BROWSER_EXECUTABLE=/ms-playwright/chromium-1234/chrome-linux64/chrome

完整安装、版本切换与回滚见部署 Linux Node。

自建 Linux Node ​

本页按仓库 deploy/node/ 的 Docker + systemd 方案部署浏览器节点（当前源码0.10.9）。需要已有 Docker 的 Linux 服务器、sudo 权限，以及已验证主机密钥的 SSH 连接；不需要 Electron 或 Linux 图形桌面。

服务仅发布到服务器 127.0.0.1:4718，Mac 通过 SSH 转发到 127.0.0.1:14718。先了解运行环境与网络连接。

1. 准备独立账号和目录 ​

先检查 UID/GID 10001；若已经被占用，先解决冲突，不直接复用无关账号。已有 OpenBot 部署保留原数据，并先停止旧实例。

shell
getent passwd 10001
getent group 10001
sudo groupadd --gid 10001 openbot
sudo useradd --uid 10001 --gid 10001 --home-dir /var/lib/openbot --no-create-home --shell /usr/sbin/nologin openbot
sudo install -d -m 0700 -o 10001 -g 10001 /var/lib/openbot
sudo install -d -m 0700 /etc/openbot
sudo install -d -m 0755 /opt/openbot/releases
docker network create --driver bridge --opt com.docker.network.bridge.enable_icc=false openbot-node

2. 构建固定版本镜像 ​

将已核验源码放入独立发布目录。下例的目录与 tag 是示例名称，执行前改成你的实际发布路径：

shell
OPENBOT_RELEASE=/opt/openbot/releases/0.10.9-verified
OPENBOT_IMAGE_TAG=openbot-node:0.10.9-verified
cd "$OPENBOT_RELEASE"
docker build -f deploy/node/Dockerfile -t "$OPENBOT_IMAGE_TAG" .
docker image inspect "$OPENBOT_IMAGE_TAG" --format '{{.Id}}'
docker run --rm --entrypoint node "$OPENBOT_IMAGE_TAG" \
  -e 'process.stdout.write(require("playwright-core").chromium.executablePath())'

Dockerfile 固定 mcr.microsoft.com/playwright:v1.62.1-noble 及已校验 digest，与 playwright-core 1.62.1 配套；生产依赖按 lockfile 安装并禁用安装脚本。不要覆盖为 latest 或另猜浏览器路径。

shell
sudo install -m 0600 deploy/node/node.env.example /etc/openbot/node.env
sudoedit /etc/openbot/node.env

在环境文件中填写以下值，模型 Key 留在私有数据目录：

变量填写内容
OPENBOT_IMAGE上方 inspect 输出的完整 sha256: 镜像 ID
OPENBOT_DATA_DIR/var/lib/openbot
OPENBOT_BROWSER_EXECUTABLE上方确认的 Chromium 绝对路径

3. 准备 Bot 与模型 ​

从桌面导出 Fleet 配置包，经受信任渠道传到服务器。首次导入或配置更新均在服务停止时执行；将下例源文件改成实际路径：

shell
sudo install -m 0600 -o 10001 -g 10001 /path/to/openbot-fleet.json /var/lib/openbot/import-fleet.json
docker run --rm --mount type=bind,src=/var/lib/openbot,dst=/var/lib/openbot \
  --entrypoint node "$OPENBOT_IMAGE_TAG" /app/node/index.js \
  import --in /var/lib/openbot/import-fleet.json --strategy replace

执行 Bot 的 ID 必须与 Mac 相同。replace 可保留已有同 ID Bot；默认 merge 遇到同 ID 会建立副本，不适合直接作为相同 Bot 的节点绑定。

Fleet 不带模型 Key，也不授予节点工具权限。在服务器受信任编辑器中按配置参考保存 config.json，使 Bot 的 providerId 匹配命名连接；在 bots.json 中核对指定 Bot 的模型、harness 与 toolsEnabled: true，只启用需要执行的 API Bot。节点浏览器不沿用本机 CLI/ACP 绑定；不要复制日常 Mac 的整套私有目录。

shell
sudoedit /var/lib/openbot/config.json /var/lib/openbot/bots.json
sudo chown 10001:10001 /var/lib/openbot/config.json /var/lib/openbot/bots.json
sudo chmod 0600 /var/lib/openbot/config.json /var/lib/openbot/bots.json

4. 启动服务 ​

先保存旧 current 指向、环境文件和整目录备份，再原子切换到已核验发布目录。首次部署执行：

shell
sudo ln -s "$OPENBOT_RELEASE" /opt/openbot/.current-next
sudo mv -Tf /opt/openbot/.current-next /opt/openbot/current
sudo install -m 0644 deploy/node/openbot-node.service /etc/systemd/system/openbot-node.service
sudo systemctl daemon-reload
sudo systemctl enable --now openbot-node.service
curl --fail http://127.0.0.1:4718/api/v1/ping

已有服务升级使用 sudo systemctl restart openbot-node.service。ping 只证明入口存活，不证明认证、模型、浏览器或任务已经可用。

5. 核对容器边界 ​

项目仓库默认值
身份与文件系统UID/GID 10001、根文件系统只读、持久数据挂载、512 MiB /tmp
浏览器沙箱丢弃全部默认能力，仅加 SYS_CHROOT，原版 seccomp 与 no-new-privileges
资源2 CPU、4 GiB 内存、1024 进程、1 GiB 共享内存
网络与日志独立 bridge、仅环回 4718、local 日志轮转
数据独占固定 hostname，入口持有整个运行期的 flock 排他锁

宿主须支持 Chromium 非特权用户命名空间。不添加 --no-sandbox、SYS_ADMIN、特权模式、host network 或 Docker socket；运行验收核对 Node 主进程 CapEff=0、CapPrm=0。

.node-instance.lock 不能删除或替换。入口仅清理旧 Chromium 的 SingletonLock、SingletonSocket、SingletonCookie 符号链接；保留登录资料。升级或故障恢复先销毁旧容器，不能绕过入口在同一目录另起服务。

6. 从 Mac 连接并验证 ​

将 openbot-server 换成你已配置并严格核验主机密钥的 SSH 别名：

shell
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:14718:127.0.0.1:4718 openbot-server

在受信任 SSH 终端显式使用节点 token 命令读取节点令牌，私下填入桌面设置；不把令牌放入 URL、命令历史、共享日志或截图。容器内命令是 node /app/node/index.js token，通过 docker exec 执行，不启动第二个服务。

桌面填写 http://127.0.0.1:14718，保存后显式连接执行会话。将相同 ID 的 Bot 的“任务与屏幕位置”选为“自建节点”。先做一项只读任务，核对结果、预览、接管和交还，再增加第二个 Bot。

一个 Node 同时只有一个控制客户端。断线或租约失效后重新建隧道、连接、核查新画面并交还；旧审批和输入不回放，Node 重启只将未完任务标为 interrupted，不重派。

7. 连接应用并授权主 Bot ​

Node就绪后，可按自托管应用授权配置独立加密仓、GitHub OAuth App与Device Flow。默认不给Bot授权，按连接/主Bot/只读动作分配；应用授权不自动打开原工具权限。

外部任务由当前主Bot在已开启工具、非Hub来源的会话中调用应用工具。普通桌面聊天、空间会话和浏览器任务没有自动获得这些工具。模型配置、健康检查、OAuth连接和Bot实际调用分别验证。

更新、回滚与排查 ​

升级前停服务，私下备份整个 /var/lib/openbot、node.env 与旧镜像 ID；新版本先用独立数据目录和不同环回端口验证。回滚恢复上一组镜像、current 和对应数据备份，不拼接两代账本。

shell
sudo systemctl status openbot-node.service --no-pager
journalctl -u openbot-node.service -n 100 --no-pager
docker inspect openbot-node --format '{{.State.Status}} {{.State.Health.Status}}'

权限错误先查目录归属，浏览器失败查精确路径与沙箱，实例冲突先确认旧服务已停。回滚不能撤销网页操作；继续前核查任务和页面。下一步见网络连接、节点 API和浏览器接管。

网站0.1.14 · 2026-10-21 ​

  • 修正结尾群像的小手：手臂根部回到角色身体轮廓内、手不再落到两个伙伴之间的空隙里，指尖仍在头顶以下，整只手不越出自己所属的伙伴。
  • 左右两侧真镜像：同一只手在指针位于左侧时水平翻转，拇指朝回身体，不再两侧都用同一只右手。
  • 手形重画为三指＋拇指＋手掌，整只手只描一次外轮廓，替换掉小尺寸下会糊成黑色条纹的逐指描边；白色手在蒜蒜这类白色角色上也靠轮廓和柔和投影分离。
  • 群像验收在挥手专项内新增几何与镜像断言（手臂根部位置、指尖高度、手的横向范围、scaleX 符号与指针侧一致），断言收紧未放宽。

网站0.1.13 · 2026-10-21（已部署阿里云 wave） ​

  • 指针靠近时，附近的角色伙伴会长出一只白色小手朝指针方向挥手欢迎，最多3个同时打招呼；暂停、离屏、减少动态效果或指针离开时收回。

  • 共享暂停、系统减少动态效果、可见性与卸载边界覆盖角色与小手；群像验收扩展为10项并新增挥手专项，断言收紧未放宽。

通信架构约定 · 2026-10-20 ​

本次为文档 0.1.2 的架构说明更新，不代表应用版本升级或新增已交付协议。

  • 同一 OpenBot 内部继续使用内部函数接口，桌面界面以 Electron IPC 调用宿主。
  • 客户端连接自己的 Node 使用现有 HTTP(S) JSON、Bearer 令牌与游标事件轮询，不称为 A2A。
  • 不同账号的独立 OpenBot 单独设置 A2A Adapter；当前尚未实现或通过互通验收。B2B 保留为 Bot 协作数据模型，不另造第二套网络协议。
  • 外部调用由接收方验证身份、权限与上下文范围，不自动共享私人记忆或凭据。

长期约定见 Bot 协作与通信边界。下方应用发布记录保持原有版本与验收范围。

0.9.1 · 2026-10-19 ​

自建 Linux Node 已实际部署并验收，提供两个独立 Chromium 浏览器屏幕。Mac 主脑可交办任务、预览与接管远端页面，读回真实结果后汇总。

  • 使用固定版本与 digest 的 Playwright 镜像、Docker 与 systemd；UID/GID 10001、浏览器沙箱和资源限制保持。
  • 服务只发布到服务器环回地址 127.0.0.1:4718，Mac 经 SSH 隧道的 127.0.0.1:14718 接入。
  • 固定容器 hostname，运行期间持有数据目录排他锁；容器重建时仅清理崩溃遗留的 Chromium 单实例符号链接，保留 Cookie 与浏览器资料。
  • 修复任务终结后旧进度仍显示处理或暂停；迟到事件不能恢复已结束状态，其他活动任务继续显示。
  • 启动日志不再输出节点主令牌。连接仍需私下配置令牌并显式连接执行会话。

0.9.0 · 2026-10-19 ​

  • Bot 可显式选择任务与屏幕在本机或自建 Node 执行；普通对话与主脑仍留在 Mac。
  • Node 使用自己的模型、Harness、持久任务队列和浏览器资料；Fleet 不自动复制模型凭据或动作账本。
  • Playwright 薄窗口适配复用 ScreenManager 的观察、串行输入与控制权规则。
  • 单控制客户端与租约使旧审批、输入在断线后失效；重连后需显式交还，重启只标中断，不自动重派。

本版只在同一 Mac 的独立进程与真实 Chromium 验收；真实 Linux 证据由 0.9.1 补充，不倒改旧版范围。跨主机有限额度和父页面完成条件移交尚未接通。

0.8.2 与 0.8.1 · 主脑反馈 ​

0.8.1 增加主脑动态反馈；0.8.2 将其与真实派单、排队、执行、授权、暂停和结果读回状态联动。只有本轮子任务终结且主脑实际读回结果后才进入汇总。

最多展示三个执行 Bot 头像，其余收为数量。关闭进度或启用减少动态效果后，审批与停止入口仍可用。此系列没有新增任务调度器或自动授权，相关旧 Web 夹具失败单列保留。

0.8.0 · 浏览器执行 Bot ​

  • 主脑可显式派发 API 浏览器任务，省略模式仍为文字任务。
  • 接收 Bot 需已开启工具，使用自己的连接、模型及 Pi/legacy Harness，只开放本屏六项浏览器工具。
  • 宿主完成核查、父轮额度共享、逐次审批、人工接管与新观察沿用既有策略；未知结果不能由模型自称完成覆盖。
  • 隐藏执行 Bot 时仍能审批和停止；停止主脑只取消该轮子任务，独立任务继续。

本版扩展动作账本后，旧版加载器会锁定不兼容数据。降级须退出应用并恢复与旧版配套的整目录备份，不能删除账本绕过保护。

0.7.0 · 贾维斯模式 ​

增加显式进入和退出的主脑协作视图。API 主脑开启工具后向已有 Bot 派文字任务，等待实际结果并汇总；执行 Bot 的身份、模型与历史保留。CLI/ACP 继续使用原有执行器。

仅进入模式不增加权限，显示模式切换不停止后台任务。后续浏览器委派由 0.8.0 增加，远端执行由 0.9.0 增加，不能混为 0.7.0 已有能力。

0.6.x 及更早 ​

0.6 系列补齐旧 Bot 身份保留、配置继承、停止与退出收尾、持久结果和升级验证。此前版本的真实模型失败仍保留，不用新版本通过结果改写历史。

例如 0.4.1 的真实服务记录为 7/8，阿里云 Pi 最小健康检测失败原因未确定；同批其他路径通过不等于该检测通过。完整旧记录继续以各版验收文件为准。

升级和证据口径 ​

升级前退出应用并备份整个实际数据目录。配置包不含 Key、Token 和浏览器登录状态，不能替代备份；未完成任务重启后中断，不重跑。

passed、failed、not_run 分别表示通过、失败与未运行。源码、最终包、受控夹具与真实模型各自记录，本地交付与 GitHub 发布也分别记录。

在源码根目录只读查看本地版本与 0.9.1 的核心验收计数：

shell
node -e 'console.log(require("./package.json").version); const v=require("./releases/0.9.1-verification.json"); for(const k of ["cloudSource","cloudPackaged","cloudLifecycle","realProviders"]){const c=v.checks[k]; console.log(k,c.status,c.passed+"/"+c.total)}'

此命令读取仓库记录，不运行验收，也不说明当前机器部署状态。下一步：快速开始、参与开发、架构与支持范围。

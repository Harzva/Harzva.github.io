参与开发 ​

当前文档面向OpenBot0.10.9源码预览。本页面向已取得源码的协作者：先在独立数据目录运行，再用与改动相关的验证说明行为变化。

准备开发环境 ​

桌面开发需要 Mac arm64、Node.js 22.19.0 或更新版本与 npm。本机浏览器验收还需 Chrome/Chromium；Linux Node 不需要 Electron，部署前提另见自建节点。

在仓库根目录执行：

shell
node --version
npm ci
OPENBOT_USERDATA="$HOME/Library/Application Support/openbot-dev" npm start

开发目录放在仓库外，不使用日常安装的数据、登录状态和模型凭据。npm ci 按根目录锁文件安装；不要为验证文档去升级运行时依赖。

先找现有入口 ​

修改范围先阅读的仓库文件
模型连接与解析src/config.js、main.js、node/execution.js
Agent 执行内核src/agent-driver.js、src/dsh-agent.js、src/pi-agent.js、src/tools.js
浏览器与控制权src/screen.js、src/screen-driver.js
Node 执行node/execution.js、src/remote-execution.js
Linux 容器deploy/node/Dockerfile、run-container.sh、entrypoint.sh
数据与交付src/persistence.js、docs/upgrading.md、releases/manifest.json

模型、Harness、执行主机与屏幕通过薄 Adapter 接入。Bot 身份、记忆、审批、动作预算和持久记录继续归 OpenBot；新增 Adapter 不另建权限状态、恢复队列或未知结果自动重试路径。

将改动限制在一个问题 ​

先描述具体触发条件和预期结果，再复用已有实现。新增功能要同时说明它在哪个执行位置生效、需要什么授权、如何停止，以及结果不确定时如何呈现。

涉及输入、审批、预算、任务归属或持久化的修改，应保留失败记录和最小复现。仅修改文档或文案时，不必为重复实现断言新增测试。

按范围验证 ​

范围命令验证重点
逻辑与策略npm test故障复现、取消、归属与契约
桌面 Web 界面npm run test:web普通和窄窗口、真实浏览器
原生浏览器npm run test:computer-use多屏、审批、输入与接管
动作预算npm run test:action-budget额度与未知副作用
观察顺序npm run test:observation新画面、失败后阻止盲操作
启动与数据迁移npm run test:upgrade旧身份、数据保留与中断恢复
Node 协议与浏览器npm run test:node-execution、npm run test:node-browser节点任务与窗口适配

Web 测试必要时用 OPENBOT_CHROME_PATH 指定浏览器可执行文件。Fleet 原生验收另需仓库外的脱敏 fleet.manifest.json，由 OPENBOT_E2E_MANIFEST 指定；缺少样本不能算通过，普通 npm test 和启动不依赖它。

验证最终安装包 ​

改变发布运行路径时，制作安装包并检查实际产物：

shell
npm run build:mac
npm run test:app
npm run test:release

产物位于 dist/，实际 .app 路径记录于 dist/.last-app-path。若重新生成图标，需要带 Pillow 的 Python，可通过 OPENBOT_PYTHON 指定解释器。

对最终包做升级检查时，显式指定其可执行文件；将下方路径替换为实际包路径：

shell
OPENBOT_E2E_APP="/path/to/OpenBot.app/Contents/MacOS/OpenBot" npm run test:upgrade

未指定时验证源码 Electron，不能替代最终包。可以用 OPENBOT_E2E_OUT 指定新证据目录，避免覆盖先前失败记录。

文档站开发 ​

文档站使用 website/ 下独立的 VitePress 工程。从仓库根目录执行：

shell
npm --prefix website ci
npm --prefix website run dev
npm --prefix website run build
npm --prefix website run check:artifact

同一份website源码用于wave和GitHub项目Pages；发布base均为/openbot/，不维护第二套正文。Pages只使用仓库内的构建产物和OIDC，无需云SSH或模型凭据。

正文使用标准 Markdown，站内链接指向已存在路由。仓库源码路径使用行内代码，避免把仓库文件当作文档站可访问页面。版本和支持能力以实际发布证据为准。

提交说明与凭据处理 ​

说明触发条件、修改后的行为、运行过的检查及未运行项。分开记录源码、Web、最终 App、受控夹具和真实模型结果；付费测试单独明确运行，不自动重跑来替换失败。

问题报告应包含版本、系统、模型/Harness 类型、最小步骤和脱敏错误。Key、Token、私人对话及浏览器资料不进入提交、截图、日志或问题描述。

新增依赖时更新锁文件并记录上游来源、固定版本和许可，按实际引入内容维护 THIRD_PARTY_LICENSES.txt。本地Git交付、远端代码、Pages站点和安装包各自登记，不把本地标签或Actions构建等同公网发布。

文档部署机制见VitePress官方指南和GitHub Pages官方指南。

官网与交互预览 ​

首页面向产品使用者，回答“能帮我做什么、如何使用、从哪里开始”。开发文档承担安装、配置、运行边界、接口和贡献说明。两者同源构建，但使用独立布局：产品页展示界面与场景，文档保留搜索、左侧目录、文章和页内导航。

内容应该放在哪里 ​

内容位置
产品价值、协作场景、浏览器屏幕体验产品首页
安装与源码命令、系统条件快速开始、使用门槛
模型、执行器、节点与资源调度模型、Harness、运行与数据
版本、支持范围、已验收与待实现支持范围、版本记录
其他独立开发者工具公开工具

新增能力时先核对实际交付，再选择合适位置。首页不展示内部版本摘要、测试数量或部署细节，也不把规划写成可用能力。

真实界面的导出 ​

scripts/build-product-preview.mjs 生成浏览器预览，复用实际 App renderer、样式与原创头像。它适配生成后的入口并注入合成资料，原生源码保持不变。预览没有桌面 preload 桥，不接入模型、真实账号、本机执行器或 Node。

界面位于 sandbox="allow-scripts" 的隔离 iframe，禁止连接外部服务；输入只留在当前预览会话。重置会创建新 iframe。界面版本来自被导出的 App 快照，官网版本与安装包版本分别登记。

手动优先与自动演示 ​

可见且闲置 20 秒后，预览可自动进入固定的 Bot / 矩阵场景，每步停留 7 秒。鼠标、键盘、点击、滚轮和触摸操作立即取消后续步骤；菜单、输入、选区和弹窗阻止接管。修改过的示例保持手动，只有明确重置才恢复演示；自动流程从不主动重置、发送消息或执行任务。

可关闭自动演示，网站只保存这一偏好；减少动态效果时默认关闭。页面隐藏、离屏、收起、失败和卸载会中止排程，重新可见后重新计时。父页面与 iframe 只交换固定场景、就绪和暂停状态，校验来源、会话、代次与请求号，不接受任意脚本或选择器。

首页动效 ​

网站0.1.7用两行反向横移的 Bot 角色介绍和主脑协作示意，展示分工与汇总。角色头像由 App 的原创角色导出，名称和职责是场景示例，不创建 Bot，也不表示正在执行真实任务。原来的可点击 App 预览与其20秒闲置规则保持独立。

角色条采用等宽内容组和一份循环副本，通过 CSS transform 无缝移动；副本对辅助技术隐藏且不可聚焦。协作示意按分配、执行、汇总三个阶段循环，不播报重复的实时通知。暂停开关同时管理这两种装饰动效，并保存偏好；鼠标悬停和键盘聚焦时暂停，离屏或页面隐藏时停止，返回后再恢复。系统开启减少动态效果时使用静态布局，仍可读到全部角色与协作步骤。

自动演示只切换真实 App 预览里的固定场景；首页动效只是帮助理解产品。两者均不发送消息、不连接模型、不执行工具。

网站0.1.8在结尾使用原创OB标志组成错落的伙伴群像。轮廓和实心黑点由原生品牌生成器在构建时提供；网页只调整配色、位置、错峰眨眼和区域内的轻微注视。没有复制参考页的蜂窝图案、背景模糊层或素材。

角色条与伙伴群像共享“首页动态效果”的开关，任一位置暂停都会同步另一区域；App预览的自动演示偏好仍独立。两个展示区域分别判断自身是否可见，离屏、页面隐藏和减少动态效果时停止。鼠标位置只在群像区域内使用，不记录、不上传，不影响按钮和键盘操作；触屏保持无需悬停也可读的布局。

本地构建与检查 ​

在 website 目录执行，使用与发布路径一致的 base：

bash
npm ci
OPENBOT_DOCS_BASE=/openbot/ npm run build
OPENBOT_DOCS_BASE=/openbot/ npm run check:artifact
OPENBOT_DOCS_BASE=/openbot/ npm run check:preview

验收包括文档路由与锚点、搜索与导航、原界面交互、重试恢复、自动演示和手动接管，以及不同宽度与主题的实际画面。动效检查用真实墙钟采样两行位移、方向、暂停和恢复，观察完整协作循环；循环接缝用实际 CSS Animation 时间边界定位，单独记录为受控定位。真实墙钟、加速时钟和模拟可见性测试分别记录，不将桌面浏览器宽度模拟写成手机真机验收。

仅检查首页动效时，在已构建并正确设置 base 的预览服务器上执行：

bash
OPENBOT_DOCS_URL=http://127.0.0.1:4198/openbot/ npm run check:product-motion

发布职责 ​

既有 wave 静态站使用独立 release、文件摘要核对和 current 原子切换；保留上一版本以便回滚。仅更新官网不需要改模型凭据、运行 Node、用户资料或安装 App。GitHub Pages 经独立公开工作流验证并发布同一份静态产物；两站都要分别回读验收，wave 更新本身不代表 Pages 已同步。

实现说明与脱敏回执在仓库 docs/web-product-preview.md、docs/web-idle-demo.md 及对应验证文件中。私有原始截图、备份和部署材料不进入公开静态包。

网站0.1.9进一步增加伙伴密度和黑点尺寸，延长眨眼可见时间，增加错峰轻微摆动；这些运动与眨眼、注视共用同一运行状态，暂停或减少动态效果时保持静态。正文和实际开始入口仍保留独立留白，不借密集装饰扩大能力承诺。

页尾导航 ​

网站0.1.10在产品页底部集中提供产品、文档与部署、模型与执行器、开源共创入口，链接使用相同部署前缀并指向真实页面或锚点。产品区段仍在首页，安装、配置、能力与参与细节由文档负责。页尾不改变App预览或其闲置规则。

群像的主脑光标、邻近连线及水波是同一区域的产品示意，采用本App头像与局部指针事件；不代表真实Bot组织或任务通信。实际交互控件保持原生语义，减少动态效果、暂停和离开页面会清理活动反馈。

平台卡片与双站镜像 ​

网站0.1.11在产品首页、文档入口及“平台与下载”页复用平台卡片，四端的信息集中维护在platforms.ts。有公开安装包的入口注明版本和架构，其他端展示实际进度及说明链接，不制造空下载按钮。服务器Node与手机控制端的用途分别说明。

wave和GitHub Pages使用相同/openbot/前缀与验收产物；Pages在隔离的公开仓库中更新静态站快照和校验清单，保留App源码与其构建来源，不推送内部开发历史。发布工作流校验文件集合、摘要和大小后才上传，不能用旧公开App源码重新构建出本次网站UI。后续两站升级须同时更新冻结产物、平台清单及验证记录。

当前系统提示与按芯片下载说明 ​

网站0.1.12在平台卡片上按浏览器实际系统显示“当前系统”提示并高亮该卡：检测在挂载后进行，识别不了就不高亮，四张卡片和各自入口保持不变，提示不构成下载或安装推荐。iPad以桌面Mac身份报告时按触点数识别为iOS。提示与深浅主题、窄屏换行和减少动态效果共存，卡片不新增动画。

“平台与下载”页的 macOS 部分按芯片分组：Apple Silicon 指向真实 v0.9.3 发布页和 SHA256SUMS 校验，Intel 明确标注暂未提供；同时补充当前只有预览渠道、运行要求和更新记录入口。没有公开包的端维持进展说明，不生成空下载按钮。

角色卡司群像与挥手小手 ​

网站0.1.13把应用角色库的20个果蔬/精灵伙伴引入首页结尾群像：底部一排站在椭圆影子上的“小队”（蒜蒜在列），上方与两侧漂浮其余角色，加上32个OB标志共52个伙伴；手机端26个、平板40个。角色SVG在构建期从renderer/openbot-produce-characters.js生成并内联，共享一份角色样式表，不引入图片或远程资源。

指针以细指针进入群像时，除主脑头像连接最近伙伴外，指针附近的角色还会长出一只白色小手，朝指针一侧举起并持续挥动，最多3个同时欢迎；把手朝向随指针在角色左/右自动翻转。小手是纯装饰SVG，不拦截任何输入；触屏不触发挥手。暂停、页面隐藏、离屏、系统减少动态效果和组件卸载都会收回小手并冻结角色动作。

平台卡片同轮按反馈重做：去边框、墨色图标、圆点加文字的安静状态、品牌色“当前系统”徽标，悬停只加阴影，不再使用彩色药丸和描边卡片。群像与卡片的验收脚本同步收紧：52/40/26数量与角色拆分、20个角色齐全且无外部引用、小手增长/挥动/回收、停态覆盖角色与小手、平台卡片布局与焦点断言全部保留。

0.1.14 把手装回角色身上 ​

0.1.13 发布后按反馈修正小手的两处问题。位置：手臂根部原先偏到角色外侧约 42% 处，手臂悬在两个伙伴之间的空隙里；现在水平位置改由 left 按角色盒计算（translateX 的百分比会按手自身宽度解析，左右两侧因此落到不同深度），根部落在身体轮廓内、手不越出自己所属的伙伴，指尖保持在头顶以下。朝向：原先两侧只是平移同一个手掌，看起来都是同一只右手；现在用 scaleX 做真镜像，拇指朝回身体，左右两侧对称。

手形同时重画为三指＋拇指＋手掌，整只手只描一次外轮廓（drop-shadow），替换掉小尺寸下会糊成黑色条纹的逐指描边；白色手在蒜蒜这类白色角色上靠轮廓与柔和投影分离。挥手仍以手腕为轴摆动，暂停、离屏、隐藏、减少动态效果和卸载时收回的边界不变。挥手专项新增几何与镜像断言：手臂根部相对角色盒的位置、根部高度、指尖高度、手的横向范围、scaleX 符号与指针侧一致；这些断言在 0.1.13 的实现上会失败，因此能拦住回退。

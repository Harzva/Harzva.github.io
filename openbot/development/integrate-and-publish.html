接入 Bot 与发布连接器 ​

开发者可以把自己的应用暴露为 MCP 服务，再用开源的 AgentApp Connector 生成各客户端所需的配置和市场提交材料。它从 Bot Studio 的单 Bot 发布场景出发，支持 WorkBuddy、千问办公、豆包工作、ChatGPT / Codex、Cursor、Claude 和 ZCode。公开源码为 0.0.4，市场材料均处于 NOT-SUBMITTED。 AgentApp Connector

把自己的应用接入 Agent 平台 ​

  1. 准备 MCP 服务。 已有 MCP 的应用可以用自己的 HTTPS 端点或可执行的 stdio 入口。只有 REST / OpenAPI 的应用，先实现一层 MCP 服务，把选定的业务操作映射成命名清楚的工具，并为工具声明参数、结果、读写副作用和授权范围。AgentApp Connector 的输入是 MCP URL 或 stdio 路径，OpenAPI 到 MCP 的映射由应用开发者实现。

  2. 生成客户端配置。 在 Node.js 18 或更新版本下克隆仓库。将示例地址替换成自己的 MCP 地址，按客户端输出的 JSON、TOML 或表单指引配置。远程地址须使用 HTTPS，回环 HTTP 可用于本机开发。

    sh
    git clone https://github.com/Harzva/agentapp-connector.git
cd agentapp-connector
node src/cli.mjs targets
node src/cli.mjs config 'https://mcp.example.invalid/mcp' --target workbuddy-http
node src/cli.mjs guide 'https://mcp.example.invalid/mcp' --target doubao-work
node src/cli.mjs config 'https://mcp.example.invalid/mcp' --target codex --auth placeholder

    如果客户端走 stdio，用 --connector-path 指定你自己可执行的 MCP 启动脚本。例如 node src/cli.mjs config --target claude-desktop --connector-path /path/to/mcp-launcher。0.0.4 仍沿用 openbot 配置键和示例工具，支持自定义端点和入口路径。发布自己的应用时，再替换包名、市场键、工具说明以及图标。通用应用档案还未成为 CLI 输入。

  3. 在目标客户端验证。 完成客户端的信任或授权流程后，验证 MCP 初始化、工具枚举、一次允许的业务调用，以及一次应被拒绝的调用。配置生成只写标准输出，示例授权字段只含占位符。实际凭据通过客户端为调用方单独配置。 各客户端本地模式

生成市场材料并提交 ​

在 AgentApp Connector 的检出目录运行以下命令。第一条重生成 marketplace/ 的材料，第二条显示各平台的审核路径和前置项，也可加 --platform workbuddy 针对单个平台查看。预检对应仓库内的发布样例，开发者需要用自己端点的验收结果逐条核对。

sh
npm run packs
node src/cli.mjs market-preflight --format text

各平台目录有 SUBMISSION.md。其中部分目录附清单、配置或请求体占位文件。用应用自己的名称、版本、图标、权限说明、隐私政策与可复现测试说明补齐材料。需要远程调用的平台还需验证服务器可达性和认证。保留提交回执，审核通过后再记录实际公开链接。 市场材料目录 · 预检步骤

目标本地配置与提交路径
WorkBuddy生成 MCP 配置。市场包按 MCP + Skill 路径准备 connector-meta.json、mcp.json、图标和技能材料，完成主体认证后提交审核。 连接器规范
千问办公 QwenWork生成 MCP 配置。仓库提供组织内提交清单和 OpenAPI 请求体占位，按组织权限与审核流程发布。 连接器管理
豆包工作生成自定义连接器填表指引和入驻清单。平台接入规范以入驻后的后台为准，当前仓库未提供可提交包。 豆包开放平台
ChatGPT / Codex本地 Codex 用 TOML。公开提交走 OpenAI 的插件审核流程，按平台当前规范准备 ZIP、MCP 配置和审核用例。 OpenAI 提交流程
Cursor生成 MCP JSON。将插件清单和相关文件放入仓库，向 Cursor Marketplace 提交仓库地址。 Cursor 提交入口
Claude本地 Claude Desktop 示例用 stdio。提交远程连接器时，按 Connectors Directory 要求提供 HTTPS 服务、认证和测试材料。 Claude 目录提交
ZCode生成嵌套的 mcp.servers 配置。官方市场接受包含 MCP 组件的插件，通过 GitHub PR 提交插件清单、市场条目和双语 README，再经维护者审核。 ZCode 贡献指南

接入已经运行的 Bot ​

  • 直接接入 Bot Studio。 在支持单 Bot 发布的桌面版本中，选择 Bot、启动发布服务，并为调用方创建独立授权。HTTP MCP 连接器使用运行时给出的 /mcp/<publicationId> 地址。需要兼容 OpenAI 聊天客户端时，启用 published.chat@1 对应的接口，使用 GET /v1/models 和 POST /v1/chat/completions。桌面发布端点默认只监听本机，可先用于本地联调。 BotEngine 对外发布说明
  • 接入自托管 Node。 从 GET /api/v1/ping 核对节点，按需启用外部集成。MCP 客户端使用单独入口发起任务，再使用交办返回的持久请求 ID 查询结果或取消。节点管理令牌应留在管理端。 Node API · 自托管应用授权
  • 统一接入不同 Bot 后端。 AnyBot-Connector 的 anybot.connector/0.1 定义调用者身份、授权、任务提交、查询、取消和回执，并提供 HTTP、MCP 与 Chat Completions 文本子集绑定。公开源码是可运行的参考 alpha，已验证隔离 TeamBot 后端。 连接器契约 · Alpha API · 绑定规范
  • 分发 Bot 角色模板。 Awesome Bot 已公开 Bot 卡片、Agent 发现索引和可下载的 Fleet 模板。开发者可以读取 awesome.bot.agent-discovery/1 和 awesome.bot.agent/1 获取角色及导入配置。 Awesome Bot 格式说明 · 市场页面
  • 在 Bot Studio 内导入 Codex 工作台。 本地工作台市场使用 openbot.codex-workbench-market/1 和 openbot.codex-workbench-plugin/1，DSH 插件通过 DSH2Codex 转译。相关工作台包已经在桌面版集成，目前为本地分发。 技术架构

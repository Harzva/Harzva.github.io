官方账号与数据服务 ​

产品架构规划，尚未上线。 本页定义 OpenBot 官方用户身份、数据保存、管理后台和服务权益的职责，不把现有 Node 主令牌、手机配对或 Bot 的 GitHub 应用授权视为已经完成的官方账号系统。

账号与部署方式独立 ​

本地单机、局域网、公网自托管和云端自托管是四种部署模式。官方账号是独立的、可选的服务层：本地用户可以登录账号使用获授权的官方服务，也可以继续仅在本机使用；自托管用户不因注册官方账号而把自己服务器的所有权交给平台。

官方账号用于确认用户身份；设备绑定确定可连接的节点；Bot授权限制可执行的动作；套餐权益定义官方提供的服务。四者分别管理。

将官方账号关联到自托管节点，需要节点拥有者明确绑定，并发放面向特定节点和权限范围的设备授权；不能让任意节点接收一枚通用官方账号令牌后自动获得管理权。

身份或凭据用途边界
官方用户账号跨设备识别同一用户，关联组织、服务权益和经授权保存的数据不自动获得用户服务器或其他成员的私有数据
Node/Hub 连接与设备凭据接入指定自托管服务和执行会话不等于官方用户身份；不在多设备间共用永久主令牌
Bot 应用授权让指定 Bot 对指定外部应用执行被授权的动作GitHub 登录不自动授予仓库、文件或邮件访问
市场作者身份识别发布者及其发布权限不自动成为所有 OpenBot 工作空间的拥有者

现有自托管 GitHub 授权原型采用单拥有者授权仓；它证明受控连接、授权和撤销路径，不证明面向公众的多用户注册、云端记忆或订阅已经可用。

登录来源与稳定用户身份 ​

计划支持微信、Google、GitHub 等第三方登录，由成熟身份服务处理登录流程，再向 OpenBot 提供统一的身份接口。OpenBot 使用稳定的内部 account_id；第三方用户名、显示名和邮箱不作为数据主键。外部身份以身份服务的 issuer + subject 唯一绑定，多个登录来源合并到同一账号必须完成验证，不能仅因邮箱或昵称相同就自动合并。

桌面及采用浏览器授权的原生客户端按OIDC/OAuth标准接入，使用Authorization Code + PKCE S256和系统浏览器授权会话；客户端属于公开客户端，不在安装包中保存服务端client secret。回调地址、state/nonce、会话撤销和短期令牌由选定SDK与宿主共同处理。这遵循RFC 8252和OAuth安全最佳实践RFC 9700。需要原生SDK的微信登录应按对应连接器和微信SDK另行接入、由账号服务校验，不能直接套用网页扫码流程。

微信网站扫码登录、微信内网页授权和原生移动应用登录是不同接入场景，需分别配置相应应用、回调及平台凭据并验收；不能把某个开源项目支持“微信”写成所有端都已可用。Google/GitHub 的平台应用也需由官方配置，开源身份服务不会替我们取得这些第三方应用凭据。

保存哪些数据 ​

账号服务保存登录身份和会话；OpenBot 业务服务保存组织、工作空间和 Bot 运行资料。不要把聊天正文、私有记忆、模型密钥或浏览器 Cookie 塞进身份服务的用户 Profile。

数据域建议位置保存与同步原则
账号标识、显示信息、第三方身份绑定、登录会话身份服务及最小账号映射仅保存必要身份信息，支持撤销与停用
团队成员、角色、设备与节点授权OpenBot 业务数据库按用户/租户核验；加入团队不自动继承所有私有数据
Bot 类、工作空间 Profile、空间 Bot 实例OpenBot 业务数据库保留现有类/实例模型和整数版本；显式选择迁移范围
聊天、个人或实例记忆、分析结果OpenBot 业务数据库；大对象放对象存储默认继续本地保存，开启云端保存时说明范围、访问者与保留策略
附件、备份和导出包隔离的对象存储元数据与归属留在数据库，下载前授权，避免公开桶
模型密钥、第三方应用 Token独立凭据仓本机凭据默认不上传；确需云端执行时另行授权托管并加密保存
套餐、配额、用量、支付事件引用权益与计费数据表不在客户端信任支付成功标记，不把模型报告用量当作完整账单

第一版登录可以只创建账号、个人租户和设备登记；账号已登录不表示已启用记忆同步。 数据上传应提供范围选择，服务变更、退出账号和本地副本保留的行为也需说明。

多用户隔离与 Bot 实例 ​

每个用户先拥有个人租户，团队以独立租户建立成员关系。这里的“全局 Bot 类”是所属个人或团队范围内的类定义，不是所有平台用户共同修改的对象。公开市场模板与用户安装后的私有 Bot 分开保存。

建议的逻辑关系如下，字段用于设计说明，不代表数据库迁移已经实现：

实体关键关联与约束
accounts / auth_subjects内部账号；外部 issuer + subject 唯一绑定
tenants / memberships个人或团队；明确账号成员身份与角色
workspaces / bot_classes均属于一个租户，跨租户引用在数据库与服务层拒绝
bot_instances唯一组合 (tenant_id, workspace_id, bot_class_id)；独立 instance_id 与配置版本
memories / memory_acl个人私有记忆绑定owner_account_id，实例私有记忆绑定instance_id；同时绑定租户/适用空间，保留来源、版本与删除标记，共享另走显式ACL
devices / node_grants绑定账号和租户；每设备独立授权、到期与撤销
entitlements / usage_events绑定租户和计量周期；用量事件使用幂等标识

租户身份由已验证会话和成员关系确定，不采信客户端随意提交的 tenant_id。所有数据库查询、文件下载、搜索索引、备份恢复、队列任务和实时订阅都需要相同的范围检查；向量检索也不能跨用户召回记忆。

租户隔离还不能代替 Bot 权限：主脑能管理其租户内的类和实例，组长只管理当前空间的成员实例，普通 Bot 只管理自己；配置管理权仍不授予读取其他成员私有实例记忆的能力。现有本机单拥有者 JSON 存储不能直接放到公网作为多用户数据库。

同步是单独的业务协议 ​

先同步用户明确选择的配置，再评估聊天、记忆和附件；凭据和浏览器资料不默认同步。服务端维护实体版本和增量游标，写入使用版本检查，删除使用可传播的删除标记，重试通过幂等标识去重。多端同时编辑时展示冲突，不用旧客户端快照覆盖新资料。

任务、审批和执行权限不能按普通文档合并。跨设备恢复仍需验证执行宿主、授权状态和取消结果；断线、重启或支付重试都不能自动重复外部副作用。设备撤销立即阻止后续在线访问，但不宣称能够远程擦除已经离线保存的全部副本。

正式上线前应验证至少两个账号、两个设备和两个租户的正反例，以及备份恢复、账号停用、团队退出、同步冲突和数据删除。传输与存储加密需要实际配置和验收，不能据此宣称端到端加密或平台无法读取全部数据。

免费与付费服务 ​

官方账号采用“基础能力免费、托管资源与增值服务付费”的产品方向；套餐名称、价格、额度和保留时长待容量与成本验证后公布。收费支持官方持续维护身份、数据库、存储、带宽、备份、计算和运营服务，不以是否自行部署作为唯一划分。

服务层拟议范围定价原则
本地与自托管基础能力本地工作空间、自有模型/执行器、自建节点不强制官方订阅；模型和自有基础设施费用由使用者承担
官方免费账号基础登录、设备登记及受限的云端服务如提供云存储/同步，必须有明确配额；不承诺无限资源
官方付费服务更高存储/同步配额、备份保留、团队能力或托管执行资源按实际承诺的权益和资源计费，服务端核验
模型调用BYOK 或未来单独提供的模型服务与账号服务、服务器计算费用区分；不默认包含在订阅内

首版维护简单的服务端权益表、用量事件和可替换支付适配层。支付回调需要验证、幂等入账和退款/到期处理；不要根据客户端回跳页面直接升级权限。订阅到期后的云端写入限制、读取/导出宽限和本地继续使用策略，应在套餐发布前明确。

管理后台与最小落地顺序 ​

复用身份服务自带 Console 管理登录来源、用户状态、会话和身份管理员；OpenBot 再提供业务后台管理租户、设备授权、套餐配额、存储用量和运行状态。身份 Console、现有单拥有者 Node 管理入口和未来平台运营后台是不同权限面，不能把现有 owner Token 暴露成所有用户的公共管理凭据。

平台管理员按职责分权并记录审计。客服与运维默认查看状态和必要元数据，不默认展示所有用户私有记忆、模型密钥或外部应用 Token；涉及用户数据的支持操作应具备明确的授权与记录。

  1. 身份闭环：复用一个身份服务，先接一个登录来源，再扩展 Google/微信；完成稳定账号、租户、设备撤销及跨用户拒绝测试。
  2. 选择性保存与同步：落地数据库/对象存储、版本冲突、私有记忆 ACL、备份恢复；明确用户可上传的数据范围。
  3. 商业化闭环：上线服务端权益、配额、支付事件与到期策略，再发布免费/付费套餐。
  4. 托管执行扩展：根据真实资源用量扩容 Node、队列与存储；保持本地/自托管入口可独立使用。

当前建议的组件复用和替代方案见账号服务开源选型。本页是开发约定与验收目标，本次文档更新没有新建官方用户服务、采集用户身份、开通支付或部署生产环境。

身份、执行与连接 ​

OpenBot 持有 Bot 身份、持久状态与责任记录。模型服务、Harness、执行机器和屏幕后端分别适配，替换其中一个部分不应隐式改变权限。

当前系统 ​

text
Mac App
  ├─ 对话与主脑
  ├─ 审批、进度、任务关系图
  └─ 代理任务与屏幕预览
           │ 显式执行连接
           ▼
自建 Node
  ├─ 持久任务、取消与审计
  ├─ 每 Bot 模型 + DSH / Pi / legacy
  └─ 每 Bot 独立 Chromium 资料与输入队列

Mac 和 Node 各自有安装身份。配置相同的 Bot ID 不代表对话、记忆、附件或凭据已经同步；当前跨主机派单依赖显式绑定与代理任务。

同一 OpenBot 内部使用宿主函数接口；客户端连接自己的 Node 使用现有 HTTP(S) JSON 接口。不同账号的独立 OpenBot 拟通过单独的 A2A Adapter 互通，该 Adapter 尚未实现。完整约定见 Bot 协作与通信边界。

四个可替换部分 ​

部分控制什么当前实现
模型服务请求协议、凭据与实际模型命名兼容 API 连接与现有网关
Harness一次任务的模型和工具循环默认DSH、显式Pi与legacy薄Adapter
执行机器工具副作用发生的位置Mac 本机或自建 Node
屏幕后端画面、输入和接管本机 Chromium 与 Node Playwright Chromium

DSH、Pi与原有循环共用 OpenBot 的工具策略、审批、取消和动作账本。尚未适配的框架不会因为模型已接通就变为可用。

常驻优先 ​

状态持久。 Bot、任务与审计应活过重启。任务中断如实记录，不静默重跑。

副作用记账。 工具动作关联执行者、任务、主机、屏幕和实际授权；缺少授权通道时不默认放行。

可以中止。 取消与撤权要传递到正在执行的任务。拒绝后不换参数反复请求同一操作。

这些规则适用于一次任务结束之后。模型给出“已完成”文字，不替代宿主确认或实际观察证据。

主脑与执行 Bot ​

主脑按职责拆解任务，向已配置的执行 Bot 派单。执行 Bot 使用自己的模型、Harness 和屏幕，主脑通过真实持久结果汇总。

贾维斯模式把组织折叠进一个对话，用户仍可展开任务、审批、用量与 Bot 箭头关系图。界面收起执行细节不减少授权要求。

连接不等于同步 ​

Node 使用自己的模型凭据与浏览器资料。客户端看到屏幕，不代表拿到了服务器文件系统或完整操作系统控制权。

当前是一个 Node 对一个执行控制客户端。断线使旧授权和旧输入失效，恢复连接后重新观察并显式交还。跨主机有限动作额度与页面完成条件暂不移交，相关主任务在入队前拒绝。

Hub 的边界 ​

独立预览Hub已用于设备配对和手机联调；日常App整合、统一账号和自动节点目录尚未交付。Node继续拥有执行和持久Bot状态，Hub与Node可部署在同一台主机。

云端 Bot 应以所属 Node 为状态来源，多端读取同一实体。账号相同不自动合并本地 Bot、不同节点的记忆或历史；数据迁移需要显式流程。

接口见 Node API，执行框架见 Harness 适配。

Model → Harness → BotEngine Runtime 架构提案 ​

Bot Studio 的分层提案以模型提供推理、Harness 执行单次任务、Runtime 持有身份与任务状态为边界。S0 后台常驻和四窗口完整恢复仍在开发。已安装、隔离试验和公开接口的范围见技术架构报告。

  1. Model 层（干线大脑与原子感知：L1 / L2）：负责单次推理与标准化外部工具调用（如检索、网页抓取、OCR、ASR、TTS），本身无长期任务生命周期。
  2. Harness 层（单程执行脚手架：L3）：负责在单一工作目录内循环执行工具、改文件与跑测试（如 dsh、agent:codex、kimi）。单程脚本退出即停，无法独立承担跨入口身份、硬件权限仲裁或断点续履约。
  3. BotEngine Runtime 层（最后一公里操作系统：L4）：负责把前三层组织成常驻数字员工——持有 Bot 身份、固定执行器绑定（D25）、宿主密钥托管、Harvis 人工审批边界、异常/断电恢复（4-window / unknown 不重放）以及带 SHA-256 校验的 openbot.task-receipt/1 交付回执。

AI API 分层提案（L1 → L4） ​

层级标准定义调用单元状态与身份治理与审批在 Bot Studio 中的协同方式
L1 大模型 API纯推理与生成接口单次请求/响应（Token 流）无状态按账号/密钥计费与限流每 Bot 可自由切换底层模型，可插拔替换
L2 工具 API原子扩展能力接口（搜索、抓取、OCR、语音）单次工具能力调用无状态 / 轻量会话宿主注钥、SSRF 拦截、密钥脱敏作为加速器内嵌进 Bot 工作台与受控桥接，不与大模型本身绑定
L3 Agent API单程工具编排与执行循环（Harness）单次 Run / 会话循环单次会话或独立 Worktree沙箱 / 工具白名单按固定执行器绑定（dsh、agent:codex、kimi 等），各展所长
L4 Bot API面向结果的常驻数字员工接口（BotEngine）任务派单 / TaskReceipt / 持续对话持久身份、私人记忆与工作区能力准入矩阵、Harvis 审批、SHA-256 交付证明通过 published.chat@1（GET /v1/models、POST /v1/chat/completions）或跨 Bot 委派直接交付成果

三视角协同工作台（源码候选方向） ​

在隔离演进候选（experiment-linked-workspace-perspectives 与 add-bot-capability-workbench）中，桌面工作台通过 BOT 视角、任务会话视角（C人工程视角） 与 文件交付视角 将同一份后端真值映射为不同工作视图：

  • BOT 视角：围绕数字员工开展日常协作、IM/API 渠道接入与 Workbench 工作台零 LLM 快捷操作（带 workbenchRevision 乐观锁与 Harvis 确认）。
  • 任务会话（C人工程视角）：展示 D25 固定执行器身份、DSH 四层概念归类与 D24 五态能力真值（installed / bound / activeInPlan / invoked / blocked），直接呈现阻塞原因而不覆盖底层安装事实。
  • 文件交付视角：串联工作区产出文件、SHA-256 校验与 openbot.task-receipt/1 签收流水。

Node API ​

本文面向0.10.9源码预览。独立的 /api/v1/app-connections 提供拥有者管理的应用授权首版，含GitHub连接、Bot只读动作分配、调用、撤销及审计。详见自托管应用授权，不代表官方多租户云服务已经上线。

下方为自托管Node的既有HTTP接口。它们不是官方云服务 API；没有统一账号、公开 SDK 或长期兼容承诺。建议从只读接口开始集成。

地址与版本 ​

默认 Node 监听 127.0.0.1:4718。下文使用通过 SSH 转发到 Mac 的地址 http://127.0.0.1:14718；部署步骤见连接与网络。

字段当前含义
应用版本当前源码 0.10.9，以实际部署返回为准
API 路径前缀/api/v1
ping.version / health.version整数 1，节点协议／数据版本
execution/describe.protocol整数 1，执行协议版本

不要把 ping.version: 1 解析为应用已经发布 1.0.0。

认证 ​

除 /ping 外，下列只读接口都需要节点主令牌：

http
Authorization: Bearer <NODE_TOKEN>

节点也兼容 X-OpenBot-Token。这份令牌属于自托管节点认证，不是模型服务 Key，也不是微信、GitHub 等账号登录会话。

示例假定令牌已通过你自己的凭据管理方式放入环境变量 OPENBOT_TOKEN。不要把真实令牌写入网页、Git 仓库或公开日志。

探测节点 ​

bash
curl --fail --silent --show-error   http://127.0.0.1:14718/api/v1/ping

示例返回：

json
{
  "ok": true,
  "app": "OpenBot Node",
  "version": 1,
  "name": "my-openbot-node",
  "auth": "bearer"
}

name 来自你的节点配置。这个请求不调用模型，也不证明执行会话或浏览器已可用。

读取节点状态 ​

以下三段代码执行同一个只读请求，可选择你使用的语言。

bash
printf 'Authorization: Bearer %s\n' "$OPENBOT_TOKEN" |
  curl --fail --silent --show-error --header @-     "${OPENBOT_NODE_URL:-http://127.0.0.1:14718}/api/v1/health"
python
import json
import os
from urllib.request import Request, urlopen

base = os.getenv("OPENBOT_NODE_URL", "http://127.0.0.1:14718").rstrip("/")
request = Request(
    base + "/api/v1/health",
    headers={"Authorization": "Bearer " + os.environ["OPENBOT_TOKEN"]},
)
with urlopen(request, timeout=10) as response:
    print(json.load(response))
js
const base = (process.env.OPENBOT_NODE_URL ?? 'http://127.0.0.1:14718')
  .replace(/\/+$/, '')
const token = process.env.OPENBOT_TOKEN
if (!token) throw new Error('请设置 OPENBOT_TOKEN')

const response = await fetch(`${base}/api/v1/health`, {
  headers: { Authorization: `Bearer ${token}` },
  signal: AbortSignal.timeout(10_000)
})
const body = await response.json()
if (!response.ok || !body.ok) throw new Error(body.message ?? '节点请求失败')
console.log(body)

只读接口 ​

方法与路径权限返回内容
GET /api/v1/ping无需令牌节点名称、协议版本与认证方式
GET /api/v1/health节点主令牌节点运行信息、Bot 数量与已有能力状态
GET /api/v1/bots节点主令牌Bot 信息及现有资料列表；可能含会话和人设

/bots 不是公开 Bot 市场。返回内容属于节点私有数据，不应直接发布给未获授权的客户端。

节点管理接口 ​

以下入口当前存在，属于需要单独授权的管理操作。此页不提供批量复制或默认开放示例。

路径方法用途
/api/v1/fleetGET、POST导出或导入配置包，导入会修改配置
/api/v1/vaultGET共享仓库资料列表
/api/v1/vault/:nameGET、PUT、DELETE读取、写入或删除资料
/api/v1/keysGET凭据元数据
/api/v1/keys/:name/valueGET读取敏感凭据；支持限定名称的作用域令牌
/api/v1/keys/:namePUT、DELETE设置或删除凭据
/api/v1/agentsGET、POST管理受限作用域令牌
/api/v1/agents/:idDELETE撤销受限令牌

这里的 agents 是节点凭据网关的授权对象，不是 Bot 列表、Harness 或组织调度接口。

实验性执行协议 ​

/api/v1/execution/* 用于现有桌面与节点的协作，当前应视为内部协议。集成前需固定 OpenBot 版本，并遵守完整的会话、审批和屏幕目标校验，不能只复制一个点击请求。

操作接口
能力描述与事件GET /execution/describe、GET /execution/events?after=0
任务与审计GET /execution/tasks、GET /execution/tasks/:id、GET /execution/audit
控制会话POST /execution/session/open、heartbeat、close
派单与取消POST /execution/tasks、POST /execution/tasks/:id/cancel
审批POST /execution/approvals
屏幕GET /execution/screens、POST /execution/screens/:botId/:operation

上表中的执行路径均需加 /api/v1 前缀。屏幕 operation 只接受 status、capture、control、input、open、close。

同一节点仅允许一个控制 session，默认租期30秒。输入需要当前主机、驱动、屏幕、控制代次与输入序号；审批也绑定当时会话与目标，并且只消费一次。

requestId 持久去重。提交结果不确定时不得换 ID 自动重派；已归档任务也不应重新执行。审批接口返回 HTTP 200 且 ok: true 只表示决定已处理，还需检查 decision.ok。

完整契约以 node/server.js、node/execution.js 和 src/remote-execution.js 为准。错误处理见错误与恢复。

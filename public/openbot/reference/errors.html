错误与恢复 ​

先区分连接失败、认证失败、执行状态冲突和任务结果不确定。不要把一次 HTTP 重试直接变成一次新任务。

错误格式 ​

节点通常返回：

json
{
  "ok": false,
  "message": "描述错误的文本",
  "code": "OPTIONAL_MACHINE_CODE"
}

code 是可选字段。普通认证错误、非法 JSON 或连接在请求体超限时被关闭，不保证都有完整 JSON 回执。客户端要同时处理 HTTP 状态、JSON 和网络错误。

HTTP 状态 ​

状态常见原因建议
400参数、任务模式或 URL 不符合要求修正请求，不重复提交同一非法请求
401缺少或使用了错误的节点令牌核对目标节点与凭据，不把模型 Key 当作节点令牌
404Bot、任务或接口不存在核对稳定 ID 与实际节点版本
409执行会话、屏幕代次或请求 ID 冲突获取新状态，按具体冲突恢复
410任务历史已归档查看记录，不将同一请求当作新任务重跑
413请求体超过2 MB缩小请求；连接也可能被关闭
429默认每 IP 每分钟240次的限制降低查询频率，避免无界轮询
503执行未启用、已关闭或持久存储不可用修复节点能力或存储，再核对任务状态

执行协议错误 ​

code含义与恢复方向
EXECUTION_UNAVAILABLE节点未启用浏览器执行，检查启动参数与实际能力
EXECUTION_SESSION_REQUIRED当前没有有效控制会话，显式连接
EXECUTION_SESSION_BUSY另一客户端持有控制会话，不能抢占式重试
STALE_SCREEN画面目标或输入序号已过期，重新获取画面
SCREEN_NOT_TAKEN_OVER当前操作要求人工先接管该屏幕
REQUEST_ID_CONFLICT同一请求 ID 被用于不同任务内容，应人工核对
API_EXECUTION_CHANGED排队或提交后执行配置已变化，不能静默套用新配置
APPROVAL_EXPIRED当时的授权已失效，旧回执不能恢复权限
APPROVAL_SESSION_MISMATCH审批不属于当前会话
TASK_ARCHIVED持久历史已归档，不重新派发副作用
EXECUTION_STORAGE_UNAVAILABLE持久化失败，先修复存储

具体错误以对应版本源码为准；内部执行协议没有独立的稳定 SDK 承诺。

浏览器打不开 ​

确认 Chromium 路径、执行用户、沙箱配置和可写数据目录。Docker 教程使用固定浏览器版本及专属资料目录；不要加入 --no-sandbox 来掩盖环境错误。

容器崩溃会留下 Chromium 单实例链接。现有入口脚本先取得整个运行期持有的排他锁，再清理三个瞬时链接，保留 Cookie 和浏览器资料。不要在浏览器运行中手动删锁，也不要绕过入口共享数据目录。

断线后的任务不确定 ​

先恢复连接并查询持久任务。requestId、节点身份与原任务归属需要保持一致；不得因为响应丢失就生成新 ID 重派。

离线取消会在重连时对账。已经发生的操作不会因取消或回滚代码而自动撤销；先检查页面、动作记录与结果，再决定是否开始新任务。

启动成功但模型不可用 ​

ping、Docker healthcheck 和模型健康检测是不同层次。节点可达不代表模型凭据有效，也不代表所选模型支持截图或工具。

健康检测会使用少量模型额度。排查时先核对保存的模型、连接和 Harness；不要用自动付费循环不断重跑同一失败。

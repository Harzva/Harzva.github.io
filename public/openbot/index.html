交给 Bot → 查看进度 → 在原会话收结果

发起任务后随时查看实时进度与工作屏幕；需要人工登录或确认时接管处理，交还后继续完成并把结果放回原对话。

  1. 1. 交给 Bot在对话里说清目标、参考文件或工作目录，分派对应伙伴执行。
  2. 2. 查看进度在执行记录和工作屏看当前步骤；需要登录或人工判断时接管再交还。
  3. 3. 原会话收结果交付文件、草稿与确认记录落回同一条对话，不丢失原有草稿和上下文。

打通 AI Agent 最后一公里的 BotEngine 运行底座

大模型负责思考，Harness 负责单程执行；Bot Studio 守在更贴近工作的 Runtime 层，把身份常驻、零推理成本的确定性动作、人工审批边界与真实交付落回桌面上。

查看架构总览了解 DSH 与执行内核

四层接口演进（L1 → L4）

每一层解决不同粒度的问题：L4 Bot API 并不是替代模型或执行器，而是把前三层稳定地组织成可交付的数字员工。

L4 · 持续身份、多端派单与可验交付

能力重心：接管 Agent 的最后一公里：身份常驻、审批边界、异常恢复与跨入口履约。

在 Bot Studio 中的角色：Bot Studio 的核心定位——把多个伙伴能力变成可被外部直接调用的真实伙伴。

DSH 四层概念 × 三视角工作台

源码演进候选方向：区分能力包、装配档案、角色预设与零模型调用工作台，并以多视角串联日常协作、工程能力检查与文件成果核验。

Bundle（能力包） · Profile（装配档案）
外部能力包保持纯净目录与清晰来源，不同伙伴各自保存身份、权限、记忆与宿主托管密钥。
Agent Preset（预设） · Workbench（工作台）
高频面板操作直达确定性执行通道，无需反复消耗大模型推理即可完成日常检查与审批控制。
BOT · 任务会话 · 文件交付（三视角协同）
按数字员工、固定执行器五态能力真值、以及交付物回执三条脉络互相关联，避免配置幻觉。

开始之前

需要云服务器吗？

不需要。可以先在 Mac 本机使用；需要远程执行时，再连接自己的 Linux 或 Docker 节点。

模型费用由谁承担？

Bot Studio 不包含模型额度。你连接的服务账户决定可用额度与费用。

现在怎样开始？

任何人都可以在本页体验示例 Bot，演示不运行真实任务。取得 Mac 试点包或主仓访问权限后，可按快速开始配置模型并完成首次对话。各入口的验证记录见支持范围。

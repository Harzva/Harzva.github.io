Bot Studio 使用指南 ​

从一个 Bot 开始。先验证它能使用你选的模型或本机智能体，再交办一项能检查结果的任务。Bot 的名字、职责和历史会保留下来，你可以按任务需要添加其他伙伴。

体验界面或安装桌面版 ​

  • 先看界面。打开首页的“点击体验”，切换示例 Bot、查看历史或展开工作屏幕。体验使用合成资料，输入留在当前演示会话。 交互预览
  • 实际跑一次。Apple 芯片 Mac 可从有权限访问的 GitHub Releases 选择带 arm64 DMG 的版本，用同页校验值核对后安装。截至 2026 年 11 月 17 日，最新带 Mac DMG 的版本是 OpenBot v0.14.0 公司试点预发布。Bot Studio 1.0.33 已在开发方本地 Mac 安装验收，尚无同版本 Releases 附件。 安装与源码启动 · GitHub Releases

页面按实际入口介绍操作。下载较早的试点包时，请以该包的发布说明和可见功能为准。手机访问、自建节点以及各平台的分发状态见平台与下载和支持范围。

新建 API Bot 或接入本机智能体 ​

你已经有什么在 Bot Studio 里怎么做
模型服务的 Base URL、API Key 和模型名新建 Bot，填职责。新建或选择一个命名 API 连接，指定模型，再选择执行内核或跟随应用默认。
已安装并登录的受支持 CLI 智能体打开侧栏底部“智能体工作空间”，核对检测到的执行器，选择并绑定给 Bot。该 Bot 使用执行器支持的模型、订阅和登录上下文。

模型生成回复并参与工具决策。Harness负责一轮执行的模型调用、工具调度和停止等流程。API Bot 可以在自己的连接上使用默认 DSH，或在版本支持时显式选用 Pi。多个 Bot 可以使用同一模型，但拥有独立的身份和任务记录。修改共享连接会影响引用它的 Bot。 模型与连接 · 执行内核

配置后先发一句短消息，核实实际答复。对于本机智能体，检测到可执行文件只能证明程序存在，真实答复还取决于登录、模型权限与额度。

交办任务、审批和核对结果 ​

  1. 选中负责这项工作的 Bot，说明输入、预期结果和可以操作的范围。第一项任务可以是“浏览我给出的公开页面，列出三个可在原文中核对的要点”。
  2. 如果要操作浏览器，在该 Bot 的设置中启用相应工具。收到审批时先看目标和参数，再批准或拒绝。要登录、输入验证码或自己操作页面时，可以人工接管。交还后，Bot 会重新观察页面。
  3. 在任务记录中查看状态与结果，并核对原文、文件或工作屏幕里的实际产物。如果结果未知，先检查原任务和外部是否已经发生操作，再决定是否发起新任务。 浏览器工作屏幕 · 错误与恢复

需要分工时，为不同 Bot 写清职责，然后由有委派权限的 API 主 Bot 分派并汇总。每个执行 Bot 仍按自己的模型、工具范围和授权执行。 主脑委派

从其他应用访问 Bot ​

入口如何启用
Telegram在桌面“应用连接”进入主 Bot 的 Telegram 设置，按界面要求配置并验证。
飞书、微信 ClawBot按自建 Node 的渠道指南分别配置。飞书使用应用机器人的长连接，微信 ClawBot 使用扫码和文字消息适配器。渠道需要独立授权和实际收发验证。
外部 MCP 客户端自建 Node 可启用 MCP stdio 入口。具备“BOT API 与 MCP 服务”的桌面版本还可显式发布一个 Bot，再按调用方授权使用 HTTP 或 MCP。发布、授权和撤销由运行 Bot 的宿主管理。

应用目录中的“待接入”卡片提供开发指引。启用渠道、登录用户账号和授权 Bot 操作第三方应用各有自己的配置。 接入 Bot 与发布连接器 · 应用授权 · 自建 Node

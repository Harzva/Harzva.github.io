1. 从干线算力到末端履约：Model → Harness → BotEngine Runtime

用物流与外卖“最后一公里理论”看 AI 工程栈：主干网络越快，末端投递的成本、地址歧义、签收信任与异常重投就越成为决定体验的真正瓶颈。

Tier 1 · Model 层（干线大脑）

L1 大模型 + L2 工具感知

提供通用推理与 Search / Fetch / OCR / ASR / TTS 原子加速。特点：无状态、按次计费、不理解个人目录或设备边界。

Tier 2 · Harness 层（单程脚手架）

L3 单次任务循环（DSH / Codex / Kimi）

把工具调用、读改代码与命令执行跑成单程闭环。特点：强深度执行，但进程退出即停，无法跨入口协同。

Tier 3 · BotEngine Runtime（最后一公里底座）

L4 Bot API · Bot Studio / OpenBot

设计覆盖常驻身份、固定执行器绑定、人工审批及 SHA-256 openbot.task-receipt/1 交付凭证。S0 和四窗口恢复仍在开发。

① 边际成本激增
痛点：点个按钮或刷新摘要也重跑全量 LLM 循环。
解法：DSH Workbench 0-LLM 确定性面板 + DeepSeek L2 工具分流。
② 最后 100 米寻址
痛点：Bundle / Profile / Preset 混淆，跨 Bot 串目录。
解法：DSH 四层概念强边界 + 纯净 {} 目录配置 + D25 隔离。
③ 信任与签收握手
痛点：明文 Key 进提示词，工具副作用无人把关。
解法：preload.js 零密钥 + 宿主注钥 + Harvis 修订绑定审批。
④ 异常与断电重投
痛点：休眠/崩溃丢上下文，或盲目重放酿成重复操作。
解法：unknown 永不静默重放 + 四窗口恢复 + 有界队列。
⑤ 全渠道末梢触达
痛点：每个前端都要单独开发 Bot 专用插件。
解法：Bot as Anything（published.chat@1 零插件直连与多端派单）。

怎么选

按你真正在意的约束挑，不为功能清单焦虑。

数据不能出本机，模型用我自己的订阅本机 OpenBot：资料/凭据留本机，DeepSeek、Qwen、CLI 执行器随你绑；飞书 IM、CLI、MCP 全都能派活。
我要多 Bot 分工，还要有人验收本机 OpenBot：接收 Bot 干活、监督者独立核验产物、任务 unknown 不糊弄——这是产品纪律，不是提示词。
就要终端里最强的单任务编码Claude Code / Codex：单任务深度与生态成熟；它们也可以作为执行器接进本机 OpenBot。
要云托管、免本地运维、团队原生协作Devin / Manus：任务在云端跑，代价是数据与工作区在云上、按平台计费。
要现成的多平台产品（含移动端）上游 openbot.run 的 OpenBot：随装随用、插件生态；与本页主角同名不同源，能力集见各自官方口径。
喜欢开源、自己搭接入网关OpenClaw：开源可改、消息渠道广；多 Bot 身份与监督核验需要自己补。

诚实边界

先说不做什么，再谈能做什么。

当前不宣称的能力：
  • 以单机单用户为主；团队协作需自部署节点（真人协作候选已实现，未做云服务）。
  • 自动 Harness × 模型选择尚未实现；已有主 Bot 显式派单和接收 Bot 保存绑定；Super 模式 Thread 直通接线正在修复。路由解释与建议属于下一步专项。
  • 当前构建为 macOS arm64、ad-hoc 签名、未公证、未公开发布；首启动性能与部分菜单路径仍在专项核查。
  • 原生 CLI/ACP 类 Bot（codex/kimi 等）沿用产品内派单；1.0.23 候选的 owner CLI 工程入口、runtime 接线及同 Bot/Thread 原生会话连续性已完成源码与真实包实测，正式升级仍待完成。对外 API/MCP 的文字通道边界保留；不把协调者派单实测表述成 Bot 自主选择会话。
  • 向外部智能体派单取决于已接入的无头适配、认证和生命周期支持；MCP 客户端能调用 OpenBot，不等于双向自动派单都已验收。
